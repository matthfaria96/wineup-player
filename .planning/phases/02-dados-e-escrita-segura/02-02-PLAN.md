`Scanner.swift`:
```swift
public struct ScanProgress: Sendable, Equatable { public var enumerated: Int; public var toRead: Int; public var read: Int; public var missing: Int; public var moved: Int; public var finished: Bool }
public final class Scanner: Sendable {
  public init(database: LibraryDatabase, batchSize: Int = 500)
  public func scan(rootID: UUID) -> AsyncThrowingStream<ScanProgress, Error>   // roda numa Task interna destacada da main; cancelamento do consumidor (onTermination) cancela a Task
  public func scan(rootID: UUID, progress: @Sendable (ScanProgress) -> Void) async throws -> ScanProgress   // forma direta usada em testes
}
```
Algoritmo (per CONTEXT: duas etapas, lotes, AsyncStream, Task cancellation):
1. Carregar a raiz; se a pasta não existe ou não é legível → `UPDATE library_root SET online=0` e retornar progress finished sem tocar em audio_file (LIB-03, armadilha 4). Senão online=1.
2. Etapa 1: `FileEnumerator.enumerate(root:isCancelled: { Task.isCancelled })`; carregar mapa `path -> (id, inode, size, mtimeNs, status)` dos audio_file da raiz numa leitura.
3. Classificar: inalterado (mesmo size+mtime+inode e present) → só `last_seen_at`; caminho conhecido com size/mtime diferente → reler; caminho novo → candidato.
4. Movidos: para cada candidato novo, procurar entre os registros da raiz não vistos nesta varredura (present ou missing) um com mesmo `(volume_uuid, inode, size)`; se exatamente um → UPDATE path/mtime/status='present'/missing_since=NULL (mantém id; play_event e release_track preservados) e conta `moved`; se 0 ou ambíguo → arquivo novo.
5. Etapa 2: ler tags (`TagReader.read`) dos novos/alterados em lotes de `batchSize`; cada lote numa `pool.write` (insere/atualiza AudioFileRecord com volume_uuid da raiz, depois `CatalogWriter.ingest`, `fallbackTitle` = nome sem extensão). Erro de leitura → grava `read_error` e segue (não derruba a varredura). `try Task.checkCancellation()` antes de cada lote; emitir progresso após cada lote.
6. Ausentes: registros present da raiz não vistos e não movidos → `status='missing', missing_since=now` + `CatalogWriter.removeFromIndex`; nunca DELETE.
7. Ao final `last_scan_at=now`. Nada é escrito fora de `pool.write` (main nunca bloqueia; a API é async).
Recuperação de cancelamento: como cada lote é uma transação, o banco fica consistente; a varredura seguinte reprocessa o que faltou.
